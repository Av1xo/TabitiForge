**Назва системи:** Дослідницько-інженерна платформа симуляції комплексних фізико-хімічних та біологічних систем «TabitiForge»

**Код документа:** ТЗ-TF-2026-01

**Статус:** Проект (Чернетка)

### 1. ЗАГАЛЬНІ ВІДОМОСТІ
* **1.1. Повна назва системи:** Дослідницько-інженерна платформа та програмний двигун багаторівневої симуляції фізико-хімічних та біологічних систем «TabitiForge» (англ. *TabitiForge Simulation Engine*). 
* **1.2. Склад розробників:** 
	* Головний розробник / Системний архітектор (Lead Engineer/ Graphics & Core Dev) Ростислав Журбенко; 
	* Науковий консультант / Дослідник (Research Lead) Сиротенко Валерія. 
* **1.3. Підстава для розробки:** Ініціативний науково-інженерний проект (R&D), що реалізується авторами з метою створення дослідницької платформи для комп'ютерного моделювання та візуалізації емерджентних систем.

### 2. ПРИЗНАЧЕННЯ ТА ЦІЛІ СТВОРЕННЯ СИСТЕМИ
* **2.1. Призначення системи:** Система призначена для моделювання емерджентної поведінки складних систем шляхом послідовного розрахунку взаємодій на рівнях: від фундаментальної математики та фізики до атомів, молекул, біополімерів та систем штучного життя.
* **2.2. Мета розробки:** Створення власного розширюваного обчислювального двигуна (Simulation Engine), що будується за принципом «Bottom-Up» (від нижчого рівня до вищого), де кожен вищий шар спирається виключно на фізико-математичні інваріанти нижчого шару.

### 3. ВИМОГИ ДО СИСТЕМИ
* #### 3.1. Вимоги до структури системи (Ієрархія рівнів)
	Система повинна мати чітку шарову архітектуру із суворими інтерфейсами взаємодії та підтримкою принципу Bottom-Up:
	 * **Level 0 (Math & Physical Primitives / Execution Core):** 
		 * Забезпечення фундаментального контуру обчислень C17 та Vulkan Compute Shaders. 
		 * Реалізація базових векторних типів, просторових структур (Spatial Hash Grid) та чисельних інтеграторів диференціальних рівнянь руху. 
	* **Level 1 (Atomic Dynamics & Chemical Bonding):** 
		* Моделювання дискретних частинок/атомів (CHNOPS) на основі статичного реєстру елементів (`Element`) та динамічного стану в пам'яті (`Atom`). 
		* Розрахунок ван-дер-ваальсових потенціалів, кулонівських взаємодій та динаміки хімічних зв'язків. 
	* **Level 2 (Biomolecules & Polymerization Engine):** 
		* Моделювання складних макромолекул, полімеризації, нуклеотидів, нуклеїнових кислот (РНК/ДНК) та конформацій білків. 
		* Реалізація механізму динамічного укрупнення деталей (**Multi-Scale Coarse-Graining**). 
	* **Level 3 (Emergent Artificial Life & Metabolism):** 
		* Симуляція самовідтворюваних молекулярних систем, протоклітин, первинних метаболічних мереж та еволюційних процесів. 
		* Підтримка двох обчислювальних контурів: **Online Realm** (активна зона високого LOD на GPU) та **Offline Realm** (фонова макро-симуляція на CPU).
* #### 3.2. Вимоги до системного стеку та архітектури пам'яті 
	* **3.2.1. Мова розробки ядра:** Чистий **C17 (ISO/IEC 9899:2018)** без оверхеду високорівневих мов та сторонніх важких фреймворків. 
	* **3.2.2. Стратегія управління пам'яттю:** 
		* Повна відсутність системних виділень/звільнень пам'яті (`malloc`/`free`) усередині гарячого циклу обчислень (Hot Loop). 
		* Використання кастомних арена-алокаторів (**Arena Allocators**) та пул-алокаторів (**Pool Allocators**). 
		* Організація даних у формі **Structure of Arrays (SoA)** із суворим вирівнюванням за межами 16/32 байт (`alignas`) для максимальної кеш-локальності на CPU та SIMD-векторизації. 
		* **3.2.3. Графічний та обчислювальний API:** Чистий **Vulkan C API (`vulkan/vulkan.h`)** з прямою трансляцією SoA-масивів у **Shader Storage Buffer Objects (SSBO)** для обчислень на Compute Shaders без додаткового перекопіювання (Zero-Copy Architecture). 
* #### 3.3. Вимоги до верифікації, тестування та дослідницького інтерфейсу 
	* **3.3.1. Python Test Harness:** 
		* Компіляція C17-ядра у динамічну бібліотеку (`.so` / `.dll`) для прямого виклику функцій з Python через `ctypes` / `CFFI`. 
		* Автоматизоване тестування модуля пам'яті та обчислювальних модулів за допомогою `pytest`. 
	* **3.3.2. Дослідження операцій та системна аналітика (Operations Research):** 
		* Використання математичного апарату оптимізації (Марківські ланцюги прийняття рішень, елементи теорії масового обслуговування) для автобалансування навантаження між CPU (Offline) та GPU (Online). 
		* Безперервний контроль фізичних інваріантів (закон збереження енергії та імпульсу) під час кроків чисельного інтегрування. 
		* Асинхронна передача часових серій (Time-Series) для аналізу в Python (`NumPy`, `Pandas`, `Matplotlib`).
* #### 3.4. Вимоги до правового статусу та ліцензування 
	* **3.4.1. Основна ліцензія:** **Apache License 2.0** для всього вихідного коду проєкту (C17 core, Vulkan shaders, Python test suites). 
	* **3.4.2. Інтелектуальна власність:** Збереження патентного захисту авторів та захист товарного знаку «TabitiForge». 
	* **3.4.3. Сумісність:** Забезпечення вільної публікації наукових результатів у відкритому доступі із можливістю створення закритих корпоративних B2B-модулів для фармацевтичного та біотехнологічного секторів.
